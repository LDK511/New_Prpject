# ADR-001: 각 마이크로서비스(회원·상품·주문·게이트웨이·알림 워커)를 어떤 언어/프레임워크로 구현할까요?

- 상태: 승인됨
- 날짜: 2026-11-15
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문 정보는 로그인한 사용자만 조회할 수 있게 만들어줘.

## 결정
**Node.js + NestJS (TypeScript) 통일** — 전 서비스를 NestJS 모노레포로 구성

근거(장점):
- BullMQ·Stripe SDK와 궁합 좋음
- 모듈·DI 구조로 엔터프라이즈 코드 일관성

## 검토한 대안
- Node.js + Express/Fastify (TypeScript) (경량 프레임워크로 서비스별 직접 구성) → 구조·규약을 직접 정해야 함 이유로 제외
- Java + Spring Boot (Spring Cloud 생태계 기반 구성) → 무겁고 빌드·기동 느림, Redis 큐 연동이 Node보다 번거로움 이유로 제외
- Go (Gin/Echo) (고성능 바이너리로 서비스 구현) → 보일러플레이트 많음 이유로 제외

## 영향
서비스 코드 구조·팀 역량·빌드/배포 방식 · 감수: CPU 집약 작업에 불리
