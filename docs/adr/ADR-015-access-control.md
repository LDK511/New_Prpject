# ADR-015: 회원 정보·주문 조회 권한과 관리자 구분은 어떻게 할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**본인 데이터만 조회 + 관리자 역할 분리** — USER는 본인 정보·주문만, ADMIN은 상품 관리·전체 주문 조회

근거(장점):
- 엔터프라이즈 운영에 적합
- 상품 등록 권한 통제 가능

## 검토한 대안
- 일반 회원만 구분(관리자 없음) (로그인 사용자는 본인 데이터만 조회, 관리자 기능 없음) → 상품 관리를 DB 직접 수정에 의존 이유로 제외
- 세분화된 RBAC(권한 단위) (역할-권한 테이블로 상품관리자·주문관리자 등 세분화) → 초기 설계·구현 비용 큼 이유로 제외

## 영향
권한 검사 위치, 상품 관리 기능 범위, 관리자 화면 필요 여부 · 감수: 역할 검사·관리자 API 추가 필요
