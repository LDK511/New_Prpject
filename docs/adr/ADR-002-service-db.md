# ADR-002: 서비스별 전용 DB는 어떤 DB 종류로 구성할까요?

- 상태: 승인됨
- 날짜: 2026-11-15
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문 정보는 로그인한 사용자만 조회할 수 있게 만들어줘.

## 결정
**전 서비스 PostgreSQL 통일 (서비스별 별도 인스턴스/DB)** — 회원·상품·주문 각각 독립 PostgreSQL

근거(장점):
- 트랜잭션·정합성 강함
- 운영·백업 방식 단일화

## 검토한 대안
- 특성별 혼합 (회원·주문 PostgreSQL, 상품 MongoDB) (상품은 문서형, 거래 데이터는 관계형) → 운영할 DB 종류 증가 이유로 제외
- 전 서비스 MySQL 통일 (서비스별 독립 MySQL) → JSON·고급 기능은 PostgreSQL보다 약함 이유로 제외

## 영향
데이터 모델링·운영 복잡도·로컬/배포 인프라 구성(docker-compose 등) · 감수: 상품 검색 등 유연 스키마엔 덜 적합
