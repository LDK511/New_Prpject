# ADR-010: 회원·상품·주문 서비스와 게이트웨이, 알림 워커를 어떤 언어/프레임워크로 구현할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**Node.js + NestJS (TypeScript)** — 모든 서비스·워커를 TypeScript NestJS 모노레포로 통일

근거(장점):
- BullMQ·Stripe SDK 연동이 쉬움
- 모듈 구조가 엔터프라이즈에 적합

## 검토한 대안
- Node.js + Express (가벼운 Express로 서비스별 최소 구성) → 구조·규약을 직접 정해야 함 이유로 제외
- Java Spring Boot (Spring Boot/Spring Cloud Gateway 기반) → 무겁고 빌드·기동이 느림 이유로 제외
- Go (Go 표준 라이브러리+경량 프레임워크) → 보일러플레이트 많고 생산성 낮음 이유로 제외

## 영향
서비스 코드 구조, 빌드·배포 방식, 개발 생산성 · 감수: CPU 집약 작업에 불리
