# ADR-014: 로그인·인증 방식은 무엇으로 할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**회원 서비스 JWT 발급 + 게이트웨이 검증** — 게이트웨이가 토큰을 검증하고 사용자 ID를 헤더로 전달

근거(장점):
- 무상태라 수평 확장 용이
- 검증 로직 한 곳에 집중

## 검토한 대안
- Redis 세션 (세션 ID 쿠키 + Redis 공유 세션 저장소) → 매 요청 Redis 조회 의존 이유로 제외
- JWT + 소셜 로그인 병행 (이메일 로그인에 OAuth 소셜 로그인을 추가) → OAuth 앱 등록·키 설정 필요 이유로 제외

## 영향
토큰 발급·검증 위치, 서비스 간 사용자 식별 전달, 보안 구성 · 감수: 토큰 즉시 폐기가 어려움(리프레시 토큰 필요)
