# ADR-012: 각 서비스에서 DB 접근은 어떤 방식으로 할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**Prisma ORM** — 스키마 파일 기반 타입 안전 ORM과 마이그레이션

근거(장점):
- 타입 안전·마이그레이션 내장
- 서비스별 스키마 관리 쉬움

## 검토한 대안
- TypeORM (데코레이터 기반 엔티티 ORM) → 마이그레이션·타입 안정성 다소 약함 이유로 제외
- Knex 쿼리 빌더 (SQL에 가까운 쿼리 빌더+마이그레이션) → 모델·타입 직접 관리 이유로 제외
- 순수 SQL (드라이버로 직접 SQL 작성) → 코드량·실수 위험 큼 이유로 제외

## 영향
스키마 마이그레이션 방식, 코드 복잡도, 성능 제어 · 감수: 복잡한 쿼리 제어 제한
