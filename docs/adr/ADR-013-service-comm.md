# ADR-013: 서비스 간 통신과 게이트웨이 API 형태는 어떻게 할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**외부 REST + 내부 REST 동기 호출** — 게이트웨이가 REST로 받고 내부 서비스도 REST로 호출

근거(장점):
- 구현·디버깅이 단순
- 도구와 문서화(OpenAPI) 풍부

## 검토한 대안
- 외부 REST + 내부 gRPC (외부는 REST, 서비스 간은 gRPC로 통신) → proto 관리 등 설정 복잡도 증가 이유로 제외
- GraphQL 게이트웨이 (게이트웨이가 GraphQL로 여러 서비스 데이터를 조합) → 게이트웨이 구현 범위·캐싱 복잡 이유로 제외

## 영향
서비스 간 결합도, 장애 전파, 게이트웨이 구현 범위 · 감수: 동기 호출로 장애 전파 가능
