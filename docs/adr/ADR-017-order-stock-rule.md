# ADR-017: 주문 생성 시 재고 차감과 서비스 간 데이터 일관성은 어떻게 처리할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**동기 호출로 재고 예약 + 실패 시 보상** — 주문 시 상품 서비스를 호출해 재고를 예약하고, 결제가 실패하거나 시간이 지나면 예약 해제

근거(장점):
- 흐름이 단순해 디버깅이 쉬움
- 재고 정합성을 즉시 확인 가능

## 검토한 대안
- 이벤트 기반 사가(보상 트랜잭션) (주문 생성·재고 차감·결제를 이벤트로 연결하고, 실패하면 보상 이벤트로 되돌림) → 구현·테스트가 복잡함, 최종적 일관성이라 상태가 잠시 어긋날 수 있음 이유로 제외
- 결제 완료 후 차감 (Stripe 결제 성공 웹훅을 받은 뒤에 재고를 차감) → 결제 후 재고 부족(초과 판매)이 생길 수 있음, 이때 환불 처리가 필요함 이유로 제외

## 영향
재고 정합성, 주문 상태 흐름, 장애 시 복구 방식 · 감수: 상품 서비스 장애가 주문 실패로 이어짐
