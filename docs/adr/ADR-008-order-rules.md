# ADR-008: 주문·재고 처리 규칙은 어떻게 할까요?

- 상태: 승인됨
- 날짜: 2026-11-15
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문 정보는 로그인한 사용자만 조회할 수 있게 만들어줘.

## 결정
**주문 시 재고 예약 + 오케스트레이션 사가** — 주문 생성 시 재고 예약, Stripe 결제 성공 웹훅에 확정, 실패·만료 시 보상 해제

근거(장점):
- 초과 판매 방지
- 결제 실패 시 보상 흐름 명확

## 검토한 대안
- 결제 성공 후 재고 차감 (Stripe payment_intent.succeeded 수신 시 재고 차감) → 동시 결제 시 초과 판매 가능 이유로 제외
- 이벤트 코레오그래피 사가 (서비스들이 이벤트를 구독해 각자 차감·보상 처리) → 흐름 추적·디버깅 어려움 이유로 제외
- 주문 시 동기 즉시 차감 (주문 서비스가 상품 서비스 REST 호출로 즉시 차감, 실패 시 복원 호출) → 부분 실패 시 정합성 깨질 위험 이유로 제외

## 영향
주문 흐름·재고 정합성·Stripe 결제 상태 연동 로직 · 감수: 예약 만료 처리 등 상태 관리 필요
