# ADR-016: Redis 대기열 기반 주문 알림의 구현 방식과 실패 처리 규칙은 어떻게 할까요?

- 상태: 승인됨
- 날짜: 2026-11-16
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누어주고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문은 로그인한 사람만 조회 가능하게 만들어줘.

## 결정
**BullMQ 작업 큐 + 재시도·실패 큐** — 지수 백오프로 재시도하고, 끝내 실패한 작업은 실패 큐에 보관

근거(장점):
- 재시도·지연·실패 처리를 기본 제공
- jobId로 중복 방지가 쉬움

## 검토한 대안
- Redis Streams 소비자 그룹 (XADD/XREADGROUP으로 받고, ACK 안 된 메시지는 XCLAIM으로 회수) → 재시도·실패 큐를 직접 구현해야 함 이유로 제외
- 단순 List 큐 (LPUSH/BRPOP으로 단순하게 넣고 꺼내는 방식) → 워커가 죽으면 메시지 유실 가능, 재시도·중복 방지 기능 없음 이유로 제외

## 영향
알림 신뢰성, 재시도·중복 방지, 워커 확장 방식 · 감수: Node.js 생태계에 묶임
