# ADR-003: 각 서비스의 DB 접근 방식은 무엇으로 할까요?

- 상태: 승인됨
- 날짜: 2026-11-15
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문 정보는 로그인한 사용자만 조회할 수 있게 만들어줘.

## 결정
**Prisma ORM + Prisma Migrate** — 서비스별 schema.prisma로 타입 안전 접근

근거(장점):
- 타입 안전·생산성 높음
- 마이그레이션 내장

## 검토한 대안
- TypeORM + 내장 마이그레이션 (엔티티 데코레이터 기반 ORM) → 마이그레이션·타입 이슈가 잦음 이유로 제외
- Kysely/Knex 쿼리 빌더 + 마이그레이션 (SQL에 가까운 쿼리 빌더 사용) → 모델링 코드 직접 작성 이유로 제외
- 순수 SQL (pg) + Flyway (SQL 직접 작성, Flyway로 스키마 관리) → 보일러플레이트·타입 관리 부담 이유로 제외

## 영향
데이터 계층 코드 스타일·스키마 관리·성능 제어 · 감수: 복잡한 쿼리 제어 제한적
