# ADR-005: 로그인·인증 방식은 무엇으로 할까요?

- 상태: 승인됨
- 날짜: 2026-11-15
- 요청: 엔터프라이즈급 쇼핑몰을 마이크로서비스로 만들어줘. 회원, 상품, 주문 서비스와 게이트웨이, 알림 워커로 나누고, 서비스마다 전용 DB를 써줘. 주문 알림은 Redis 대기열로 처리하고, 회원 정보와 주문 정보는 로그인한 사용자만 조회할 수 있게 만들어줘.

## 결정
**JWT + 게이트웨이 검증** — 회원 서비스가 JWT를 발급하고 게이트웨이가 검증한 뒤 사용자 ID를 헤더로 전달

근거(장점):
- 무상태라 수평 확장이 쉬움
- 각 서비스에 인증 로직 불필요

## 검토한 대안
- JWT + 서비스별 검증 (각 서비스가 공개키로 직접 JWT 검증) → 검증 코드가 중복되고 키 배포 필요 이유로 제외
- Redis 세션 (세션 쿠키를 Redis에 저장하고 게이트웨이에서 조회) → 요청마다 Redis 조회, 모바일 대응이 불편 이유로 제외
- 외부 IdP(Keycloak/소셜 로그인) (OIDC 표준 인증 서버에 위임) → 인프라와 설정이 무거움 이유로 제외

## 영향
보안 구조·서비스 간 사용자 식별 전달·회원/주문 조회 보호 방식 · 감수: 토큰 즉시 폐기를 위해 refresh/블랙리스트 필요
